DAY 3 - LangChain & Memory in AI Agents
=========================================

THEORY
======

LangChain
---------
Open-source framework for building applications powered by LLMs.
It connects models, prompts, memory, tools, and agents into one pipeline.

Architecture:
  Your App -> Chains/Agents -> Prompts + Memory + Tools -> LLM Wrapper -> LLM

Components Explained:
  Prompt Templates : Reusable prompt structures with variable placeholders
  LLM Wrappers     : Connectors to OpenAI, Gemini, Anthropic, Hugging Face
  Chains           : Link multiple operations sequentially
  Output Parsers   : Convert raw LLM output into structured formats (JSON, lists)
  Memory           : Store and retrieve conversation history / context
  Tools            : External functions the agent can call (search, calculator, DB)
  Agents           : AI that decides which tools to use and in what order


Memory in AI Agents
-------------------
Memory = the ability of an AI agent to remember information from previous
interactions and use it in future responses.

Without memory, every conversation starts from scratch.

Why Memory Matters:
  - Maintain conversation context across turns
  - Improve user experience (no need to repeat yourself)
  - Enable personalised AI responses
  - Help agents complete long, multi-step workflows
  - Reduce repeated user input

Four Types of Memory
---------------------

1. Buffer Memory
   Stores the ENTIRE conversation history in sequence.
   Every user message and AI response is saved.
   + Simple, complete history
   - Grows indefinitely; hits token limits on long conversations

   Example:
     Turn 1: User: "My name is Vighnesh"  | AI: "Nice to meet you, Vighnesh!"
     Turn 2: User: "What is my name?"     | AI: "Your name is Vighnesh."
     (AI remembers because full history is in context)

2. Summary Memory
   Creates a short summary of the conversation and stores only key points.
   Long history is compressed into a paragraph.
   + Avoids token limit issues
   - Some detail is lost in compression

   Example:
     Long chat about a project -> Summary: "User is building a RAG chatbot
     using FastAPI and Groq LLM. They need help with chunking logic."

3. Window Memory
   Keeps only the last K interactions (e.g. last 5 turns).
   Older messages are automatically dropped.
   + Bounded token usage
   - AI forgets things said early in the conversation

4. Entity Memory
   Stores important FACTS extracted from the conversation.
   Not the whole history - just key entities and what is known about them.
   + Very efficient; exactly the right information
   - Needs extraction logic to identify facts

   What it stores:
     Person Name   -> "Vighnesh"
     Company       -> "TechCorp"
     Location      -> "Mumbai"
     Skills        -> "Python, FastAPI"
     Dates         -> "Interview on Monday"
     Projects      -> "RAG Chatbot"

Comparison Table:
-----------------
  Memory Type    | What is stored          | Token usage | Detail
  ---------------|-------------------------|-------------|--------
  Buffer Memory  | Full conversation       | Grows large | Complete
  Summary Memory | Compressed summary      | Small       | Approximate
  Window Memory  | Last K messages         | Fixed       | Recent only
  Entity Memory  | Key facts (entities)    | Minimal     | Specific facts


CODE EXAMPLES
=============

1. Buffer Memory Bot (LangChain)
----------------------------------
# From: Code/DAY4/BufferMemoryBot/BufferMemoryBot.ipynb

from langchain.memory import ConversationBufferMemory
from langchain.chains import ConversationChain
from langchain.llms import OpenAI

memory = ConversationBufferMemory()

conversation = ConversationChain(
    llm=OpenAI(),
    memory=memory,
    verbose=True
)

conversation.predict(input="My name is Vighnesh")
conversation.predict(input="What is my name?")
# AI remembers: "Your name is Vighnesh."

# memory.chat_memory.messages -> full list of all turns

from langchain.memory import ConversationSummaryMemory
